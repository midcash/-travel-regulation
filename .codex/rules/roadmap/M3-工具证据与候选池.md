# M3：工具、Evidence Registry 与 Candidate Pool

## 1. 阶段目标

把外部旅行数据访问从 `knowledge.py` 中拆出，通过 Port/Adapter 获取严格类型化结果；建立证据注册表、TTL/冲突语义和标准候选池。M3 交付可信数据底座，不编排行程。

## 2. 前置条件

- M2 可输出 RouteDecision、required capabilities 和 ConstraintSnapshot；
- Clock Port 可用；
- strict 模式、零重试、禁缓存回退持续生效；
- 工具 Fake 未配置调用会失败；
- 已配置供应商必须可执行 `live_tool` contract，真实 API 失败阻断阶段且不得换源。

## 3. 允许修改范围

- `src/ports/` 下工具、Evidence Repository、Clock；
- `src/infrastructure/tools/` 下高德/途牛 Adapter；
- `src/domain/models/evidence.py`、`candidates.py` 的兼容扩展；
- Evidence Registry、Candidate Normalizer/Pool；
- `knowledge.py` 的迁移 Facade；
- contract/integration fixtures 与测试。

## 4. 禁止事项

- 不实现 Task Graph 或多 Research Agent 并发；
- 不生成每日行程；
- 不做备用供应商自动切换；
- 不做自动重试、断路器、缓存读取或 stale-while-revalidate；
- 不用历史价格、默认价格或 LLM 猜测填空；
- 不把原始供应商 JSON 直接传给下游；
- 不将错误结果包装成空列表；
- 不在 domain 中 import httpx/OpenAI/供应商 SDK。

## 5. Port 设计

按能力拆分，避免万能 `ToolProvider`：

```python
class GeoProvider(Protocol): ...
class TransportProvider(Protocol): ...
class StayProvider(Protocol): ...
class PlaceProvider(Protocol): ...
class ContextProvider(Protocol): ...
class EvidenceRepository(Protocol): ...
class Clock(Protocol): ...
```

每个 Provider：

- 输入为领域 Query DTO；
- 输出为不可变 Provider Result DTO；
- `async` I/O 接口；
- 明确 timeout 参数；
- 错误抛类型化 ToolError；
- 不返回 `dict` 或供应商特有对象；
- 不负责状态写入、候选排序或用户文案。

## 6. Adapter 规范

### 6.1 HTTP 与安全

- M3 统一使用注入的 `httpx.AsyncClient`；
- URL、Key、timeout 只能由组合根从 `Settings` 注入，Adapter 不得调用 `os.getenv`、`load_settings()` 或 dotenv；
- 组合根按能力创建 Adapter：未启用的供应商不装配；已启用但缺少必需 Key 时在装配阶段抛出 `ToolConfigurationError`，不得等到首次请求才静默跳过；
- 同一请求生命周期内，所有 Adapter 使用同一个不可变 Settings/客户端配置快照；禁止 Adapter 修改 Settings 或自行重新读取环境；
- Key 只进入 Header/Query，不进入日志；
- 状态码、超时、网络错误、非法 JSON、业务错误分别映射；
- 响应大小设置上限；
- 外部文本清除 HTML/控制字符，并标记不可信；
- Adapter Span 记录 provider、operation、status、duration，不记录完整 payload。

### 6.2 错误语义

至少：

- `ToolConfigurationError`；
- `ToolTimeoutError`；
- `ToolTransportError`；
- `ToolAuthenticationError`；
- `ToolRateLimitError`；
- `ToolResponseSchemaError`；
- `ToolEmptyResultError`；
- `ToolBusinessError`。

M3 所有错误直接上抛到调用者；不重试、不换源、不返回空成功。

### 6.3 迁移 knowledge.py

- 为现有公开入口保留临时 Facade；
- Facade 内调用新 Provider；
- 新代码禁止 import `src.tool.knowledge`；
- 给出调用者列表和 M4 删除计划；
- 旧代码中硬编码“今天日期”必须移除，改用 Clock；
- 旧代码中环境变量读取迁移到组合根。
- 迁移完成后，`knowledge.py` Facade 及所有新 Provider/Adapter 均不得读取环境变量；需要配置时通过构造函数接收已校验的 Settings 或专用 ProviderConfig DTO。
- `knowledge.py` Facade 不得在内部创建默认 Adapter、默认 Key 或隐式 Fake；缺失依赖必须显式失败并向上游传播。

## 7. Evidence Registry

EvidenceItem 必须包含：

- `evidence_id`、entity_id、fact_type、typed value；
- provider/source、source_ref；
- `observed_at`、`valid_until`；
- confidence、status；
- `raw_payload_ref`，不嵌入原始 payload；
- query fingerprint；
- schema version。

Registry 负责：

- 注册证据并生成稳定 ID；
- 按 entity/fact/query 获取当前快照；
- 使用注入 Clock 判断 stale；
- 保留来源冲突，禁止最后写覆盖；
- 生成不可变 EvidenceSnapshot；
- 计算 coverage、freshness、conflict、missing 指标；
- 原始 payload 仅保存在受控存储引用中。

开发期规则：stale、conflicting、missing 都不是可用 VERIFIED 证据；关键证据不完整时 G2 将失败。

## 8. TTL 策略

TTL 为策略配置，不散落魔法数。初始类别：

- 静态地理实体；
- 营业时间/政策；
- 天气预报；
- 航班/车次；
- 酒店/门票报价与库存；
- 汇率。

M3 只实现 TTL 与 stale 判定，不实现缓存回退。测试通过 FakeClock 精确推进边界时间。

## 9. Candidate Pool

Candidate 使用 discriminated union：

- `TransportCandidate`；
- `StayCandidate`；
- `PlaceCandidate`；
- `ContextCandidate`（只在适合进入规划时使用）。

规范化：

- 统一 ID、名称、坐标、时区；
- 价格统一为总价、币种、包含项和价格证据；
- 时间统一为带时区 datetime；
- 评分保留来源与量表，不能直接跨源比较；
- 证据引用必填；
- 去重保留 merge provenance；
- 硬约束剪枝返回 reject reason，不静默丢弃；
- 不在 M3 做用户体验综合排序。

## 11. 测试矩阵

每个 Adapter 必须覆盖：

- 正常响应；
- 401/403、429、4xx、5xx；
- timeout、连接失败；
- 非 JSON、Schema 漂移、空结果、业务错误；
- 超大响应；
- 恶意/注入型外部文本；
- Key 不出现在日志/异常；
- 调用次数严格为 1。

Evidence：注册、快照、TTL 边界、stale、冲突、多来源、缺失、不可变、Clock 注入。

Candidate：标准化、币种/时区、去重、硬约束剪枝、拒绝原因、证据完整性。

contract tests 对 Fake 和真实 Adapter 使用同一套行为契约。新增代码覆盖率 ≥ 90%。


### 11.1 Live Tool Gate

- 高德和途牛真实 Adapter contract 测试标记 `slow`、`live_tool`，使用真实 Key 和受控 Query；
- 每个启用供应商至少覆盖认证、正常响应、Schema 解析、空结果和一次调用预算；429/5xx/timeout 等不可控故障由 Offline 故障注入覆盖；
- Live contract 与 Fake contract 共用同一行为断言，但真实响应必须额外记录 provider、schema version、延迟/成本和脱敏失败摘要；
- 真实工具失败不得返回空列表、切换供应商或使用历史价格；M3 阶段保持 FAILED。
Offline contract 使用 Provider Fake、HTTP Stub 和 FakeClock 稳定复现认证失败、429、5xx、超时、非法响应、空结果、Schema 漂移、过期和冲突；Live contract 失败时不得切换 Fake，Fake contract 通过也不能证明供应商可用。

真实 API 验收由用户负责手动执行。Codex 不自动调用高德、途牛或其他真实供应商，只准备受控 Query、contract 断言和脱敏报告格式。用户应通过 `start-local.ps1` 或本阶段明确的等价启动方式加载供应商 Key；未提供人工执行结果时，Live Tool Gate 状态为 `PENDING_MANUAL_ACCEPTANCE`，不得标记 M3 完成。

## 12. 阶段验收门

- [ ] 新代码不再依赖 `knowledge.py`；
- [ ] Provider 不泄露供应商结构；
- [ ] 所有 Candidate 都有 Evidence 引用；
- [ ] stale/conflict/missing 可确定性复现；
- [ ] 工具失败显式抛错且只调用一次；
- [ ] Adapter/Facade 不读取环境变量、不创建隐式配置或默认 Fake；
- [ ] 缺少已启用供应商 Key 在组合根装配阶段失败，未发起网络调用；
- [ ] Adapter 使用组合根注入的同一 Settings/客户端配置快照；
- [ ] 无 retry/cache/fallback；
- [ ] M4 可只依赖 Port、Registry 和 Candidate Pool；
- [ ] 真实 API contract 测试标记 `slow`、`live_tool`，默认不运行且由用户手动执行；
- [ ] M0/M1 的 Live LLM Smoke 回归通过，且工具与 LLM 失败均未触发 Fake-only 成功。
