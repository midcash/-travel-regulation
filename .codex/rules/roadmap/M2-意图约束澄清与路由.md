# M2：意图、约束、澄清与 Interaction Router

阶段状态：已验收（2026-07-30）。完成报告：`evaluation/reports/M2-completion.md`；交接报告：`evaluation/reports/M2-handoff.md`；ADR：`.codex/rules/adr/ADR-002-m2-hybrid-routing-and-constraint-priority.md`。

## 1. 阶段目标

把自然语言请求稳定转换为 `TripRequest + ConstraintSnapshot + RouteDecision`，在真正阻断规划时产生最少必要澄清问题。M2 只回答“用户要做什么、信息是否够、下一步走哪条路径”，不研究外部事实，不生成行程。

## 2. 前置条件

- M1 核心模型、StateRepository、Facade 验收通过；
- TripState 支持 COLLECTING、CLARIFYING、FAILED 转换；
- strict 模式和零网络测试持续有效；
- M0 Live LLM Smoke 已通过，且本阶段可使用受保护的真实 API Key。
- M1 JSON Schema 已冻结为 v1。

## 3. 允许修改范围

- `src/agents/request_interpreter.py`；
- `src/application/interaction_router.py`；
- `src/domain/services/constraint_service.py`；
- G0/G1 所需的最小 validator；
- `src/ports/llm_gateway.py` 与现有 DeepSeek Gateway 的迁移 Adapter；
- 澄清相关 Use Case、Prompt 和测试；
- Negation Guard 的接口适配与回归修复。

## 4. 禁止事项

- 不调用地图、酒店、航班、门票、天气等外部工具；
- 不创建 Evidence 或 Candidate 实例冒充真实结果；
- 不生成每日行程；
- 不实现 M3 Adapter、M4 Task Graph、M5 Critic；
- 不将 Router 简化成纯关键词 if/else；
- 不将 Router 完全交给 LLM；
- 不因缺少非关键偏好而反复追问；
- 不把 Negation Guard 结果直接全部标记为 hard。

## 5. 处理流水线

```text
RawUserInput
  → G0 确定性安全/格式预检
  → RequestInterpreter（结构化语义解析）
  → Pydantic Schema 校验
  → ConstraintService（归一化、合并、冲突）
  → ReadinessEvaluator
  → InteractionRouter
  → RouteDecision 或 ClarificationRequest
  → 更新 TripState
```

### 5.1 G0 预检

负责：

- 输入类型、长度、控制字符；
- 认证/权限上下文存在；
- PII 标记与脱敏引用；
- 显式危险/越权动作；
- Prompt Injection 风险标记；
- 空输入和明显非法日期格式。

G0 不负责地名消歧、完整语义判断和旅行事实核验。

### 5.2 RequestInterpreter

输入：原始输入引用、会话摘要、当前 TripState、允许的 mode。

输出必须严格符合：

```text
InterpretationResult
  mode_hint
  extracted_entities
  constraint_candidates
  explicit_questions
  references_to_current_plan
  field_confidence
  overall_confidence
  safety_flags
```

规则：

- 使用结构化输出或 JSON Schema；
- 未知字段拒绝；
- LLM 返回非法 JSON、缺字段或枚举非法时直接失败；
- Prompt 中用户文本放在明确数据边界内；
- 不记录完整原始输入；
- 模型不得生成旅行事实和价格；
- 模型 confidence 仅作为信号，不能绕过代码校验。

### 5.2.1 Live LLM Gate

M2 必须使用真实 LLM 验证 `RequestInterpreter`，不以 Fake-only 结果验收：

- 测试标记为 `slow`、`live_llm`，固定 8～12 条核心用例，每条至少运行 2 次；
- 覆盖 PLAN、CLARIFY、COMPARE、REFINE、双重否定、hard/soft 冲突、Prompt Injection 和非法/边界表达；
- 只断言结构化指标：Schema 通过率、关键字段召回、hard/soft 分类、否定约束召回、澄清 blocker 精度和安全标记；不比较完整自然语言；
- 固定模型、Prompt/Schema 版本、调用预算和超时，`retry_count=0`；
- 真实输出解析失败或指标低于阶段阈值时阻断 M2，不切换 Fake 或默认 PLAN；
- 失败响应脱敏后进入 Fixture，增加 Offline 回归，再重新执行 Live Gate。

本阶段实际验收使用 `start-local.ps1 -LiveSmoke`，模型固定为 `deepseek-v4-flash`。固定数据集包含 9 条用例，每条运行 2 次，共 18 次；安全用例由 G0 阻断，实际网络调用为 14 次。脱敏结果位于 `evaluation/reports/M2-live-interpreter.json`。真实 API 验收由获得授权的验收执行者运行；未运行或失败时不得标记 M2 完成。

Offline 测试必须显式注入 LLM Fake，覆盖非法 JSON、空响应、字段缺失、超时、注入文本和预算耗尽；未注入 Fake 时立即失败，不得返回默认 `PLAN`。Live Gate 通过前，Fake/Fixture 结果不能作为 M2 验收证据。

### 5.3 ConstraintService

负责：

- 日期、币种、人数和地名文本的规范化；
- hard/soft/assumption/unknown 分类；
- 来源优先级：当前用户明确输入 > 当前用户确认 > 当前旅程假设 > 画像建议；
- 同类约束合并；
- 互斥约束形成 conflict group；
- 生成新 Snapshot，不修改旧 Snapshot；
- Negation Guard 作为召回特征，与语义解析交叉校验。

必须覆盖复杂否定：

- “不是非要住五星级”不是禁止五星；
- “除了周三都可以”是时间范围约束；
- “不要太贵，但酒店可以好一点”包含软预算与局部优先级；
- “不能爬山，最好少走路”分别为 hard 与 soft。

### 5.4 ReadinessEvaluator

仅以下情况进入 CLARIFY：

- origin/destination 无法确定；
- 日期或 duration 无法推导；
- 人数/特殊人群影响票务与安全；
- 预算语义冲突；
- hard constraint 自相矛盾；
- ACTION 缺少授权或必要身份前提；
- REFINE/REPLAN 没有可引用的当前计划。

非阻断缺失形成用户可见 assumption，但 assumption 不得代替 API 失败。

澄清要求：

- 一次最多 3 个问题；
- 按信息增益和阻断程度排序；
- 问题必须能映射到具体字段或 conflict group；
- 不问系统能从已有上下文确定的问题；
- 用户回答后只更新相关约束并重新评估。

### 5.5 Interaction Router

RouteDecision：

```text
mode
confidence
reason_codes
required_capabilities
missing_blockers
risk_flags
current_plan_ref
```

决策顺序：

1. G0 安全与权限；
2. 显式 ACTION；
3. 当前计划上的 REFINE/REPLAN；
4. CLARIFY；
5. ANSWER/COMPARE/PLAN；
6. 无法可靠识别则 CLARIFY，不猜测。

Router 为混合实现：确定性优先级 + Interpreter 语义结果 + Schema 校验。

## 6. 状态与错误

- COLLECTING → CLARIFYING：存在 blocker；
- CLARIFYING → COLLECTING：用户补充后重新解释；
- COLLECTING → RESEARCHING：PLAN/COMPARE 且就绪；
- 当前阶段不得直接进入 DRAFTING；
- 解析/Schema/配置异常 → FAILED；
- 用户输入暂时不足属于 CLARIFYING，不属于系统失败。

错误代码至少包括：INPUT_EMPTY、INPUT_TOO_LONG、INTERPRETATION_INVALID、CONSTRAINT_CONFLICT、MISSING_BLOCKER、ROUTE_UNCERTAIN、PLAN_CONTEXT_MISSING。

## 7. 实现顺序

1. LLMGateway Port 和 Fake；
2. InterpretationResult Schema；
3. G0 validator；
4. RequestInterpreter；
5. ConstraintService；
6. ReadinessEvaluator；
7. ClarificationBuilder；
8. InteractionRouter；
9. TripState 集成；
10. CLI/Facade 接入并保留现有 PLAN 行为。

## 8. 测试矩阵

至少覆盖：

- ANSWER、PLAN、COMPARE、REFINE、REPLAN、ACTION、UNSUPPORTED；
- 中文/英文日期、相对日期、跨年、时区；
- 多目的地、多同行人；
- hard/soft/assumption/unknown；
- 双重否定、局部否定、范围否定；
- 冲突约束；
- 低 confidence；
- LLM 非法 JSON、缺字段、额外字段、错误枚举；
- Prompt Injection 文本不改变系统 Schema；
- 澄清问题最多 3 个且只问 blocker；
- REFINE 无当前计划；
- 同一输入重复解析的稳定性；
- 模型/配置错误显式 FAILED，无 fallback；
- Live Interpreter Eval 达到 Schema、约束召回和澄清精度阈值；

新增代码覆盖率 ≥ 90%；ConstraintService 与 Router 分支覆盖 ≥ 95%。
