# M7：计划版本、最小持久化与局部重规划（进阶差异化）

## 1. 阶段定位

M7 在 `JOB_READY` 之后实现商务差旅状态型 Agent 能力：计划跨进程保存、多轮 REFINE、会议/交通/酒店变化的确定性影响分析和局部 REPLAN。它是高价值进阶项，但不是求职项目完成条件。

本阶段只处理用户显式修改或显式输入的差旅事件，不订阅外部事件，不实现 Action 和反馈学习。临行实时路况刷新只能由用户显式触发；系统不后台监控位置或交通。

## 2. 前置条件

- M6 已标记 `JOB_READY`；
- API、Eval、Trace 和 strict E2E 稳定；
- Plan/Evidence/Constraint/RepairPatch 版本契约稳定；
- M5 Targeted Repair 已证明最小影响范围。

## 3. 允许修改范围

- `src/application/replan_controller.py` 和 REFINE/REPLAN Use Case；
- `src/domain/services/impact_service.py`；
- Plan/State/Evidence Repository Port；
- `src/infrastructure/persistence/sqlite.py`；
- TravelEvent、ImpactReport、PlanDiff；
- CLI/API/Demo 的 plan history、refine、replan、diff；
- 对应测试和 Eval 场景。

## 4. 禁止事项

- 不实现 Confirmation、G6、ActionAdapter、预订、付款或取消；
- 不实现 FeedbackRepository、长期画像或在线学习；
- 不持续追踪位置或自动订阅天气/交通事件；
- 不自动覆盖已确认/当前计划；
- 不引入 retry/cache/provider fallback；
- 不用 LLM 猜测全文差异或影响范围；
- 不允许旧 base version 覆盖新版本。

## 5. 最小生命周期

M7 必须支持：

```text
COLLECTING → RESEARCHING → DRAFTING → VALIDATING
VALIDATING → READY
READY → REFINING → VALIDATING
READY → STALE → REPLANNING → VALIDATING
任意执行态 → FAILED
```

规则：

- 转换只通过 StateTransitionService；
- 记录 actor、reason、from/to、timestamp、trace_id；
- 每次修改产生新 plan version；
- FAILED 不自动成功；
- 旧版本只读保留；
- 本阶段 `READY` 只表示可交付计划，不表示已预订。

## 6. SQLite 最小持久化

仅实现 StateRepository、PlanRepository、EvidenceRepository。

要求：

- schema version 和 migration；
- 事务保存 state + plan version + audit event；
- optimistic concurrency；
- 外键、唯一约束和稳定 ID；
- Money 使用最小单位或精确 Decimal；
- datetime 以 UTC 存储；
- PII 最小化并与运行 Trace 分离；
- 原始供应商 payload 只存引用；
- Repository 不执行业务状态转换；
- InMemory 与 SQLite 共用 contract tests；
- 每个测试使用独立临时数据库。

## 7. REFINE

支持类似：

- “会议提前到上午九点”；
- “会议地点改到浦东”；
- “酒店改到会场附近”；
- “不要红眼航班”；
- “预算再降低 1000 元”。

流程：

1. 解析修改为 `ConstraintPatch` 或 `PlanPatchRequest`；
2. 校验 base version；
3. 识别受影响 constraint/plan item；
4. 生成 ImpactReport；
5. 只重跑受影响 Task、Composer Patch 和 Gate；
6. 最后 G0～G5 全量验证；
7. 保存新版本和 PlanDiff。

修改 hard constraint 冲突时回 CLARIFYING，不擅自放宽。

## 8. 用户触发 REPLAN

TravelEvent 至少支持用户明确告知的：

- 航班/车次取消或延误；
- 会议时间、地点或持续天数变化；
- 酒店取消、不可用或政策状态变化；
- 用户要求刷新机场/车站到酒店或会场的市内交通；
- 公司政策版本变化；
- 用户临时改变日期、出发地、交通偏好或住宿要求。

```text
TravelEvent
  event_id
  event_type
  source
  observed_at
  affected_entity_ids
  evidence_refs
  confidence
  payload_ref
```

外部事实仍需 Tool 核验；核验失败则 FAILED，不使用用户描述自动升级为 verified Evidence。

## 9. ImpactService 与 ReplanController

ImpactReport 包含：

- direct affected plan items；
- downstream dependencies；
- affected date windows；
- budget delta scope；
- evidence to refresh；
- repair level：NONE、LOCAL、STRUCTURAL。

影响计算基于稳定 ID 和依赖图。ReplanController：

1. 校验事件和 base version；
2. 注册新 Evidence；
3. 生成 ImpactReport；
4. 标记当前版本 STALE；
5. LOCAL 创建最小 Task/Patch；
6. STRUCTURAL 回 M4 生成新骨架；
7. 运行相关 Gate 后全量终验；
8. 保存新版本和结构化 diff。

不得删除旧版本，不得修改无关计划项。

## 10. PlanDiff

必须结构化表示：

- added、removed、moved、updated items；
- time/cost changes；
- new/expired evidence；
- constraint/risk changes；
- unchanged item count；
- change reason 和 base/new version。

用户文案从 PlanDiff 生成，不使用 LLM 对两份全文自由比较作为真值。

## 12. 测试矩阵

- Persistence：事务回滚、migration、外键、并发冲突、重启恢复、PII 分离；
- Version：旧 base、重复 Patch、并发 Patch、版本连续性；
- Impact：NONE/LOCAL/STRUCTURAL、直接/级联影响、跨日范围；
- Replan：会议变化级联、航班替换、required night 增减、酒店/市内交通局部修改、相关 Gate、全量终验、旧版本保留；
- Failure：证据刷新失败、非法事件、悬空 ID、预算耗尽；
- E2E：创建→REFINE→diff；创建→用户事件→STALE→REPLAN→diff。

状态转换和并发控制覆盖率 ≥ 95%，新增代码 ≥ 90%。

### 12.1 Live Replan Gate

M7 必须继承并重跑 M6 Live Gate，并用真实 LLM/工具验证最小 REFINE/REPLAN 切片，覆盖局部修改、用户事件触发的证据刷新和失败案例，关键案例至少重复 2 次。SQLite、并发冲突、证据刷新失败和预算耗尽继续用显式 Fake/Fixture/故障注入；真实 LLM/工具失败阻断 M7，不得用 Fake、旧 Evidence 或部分计划替代。

真实 API 验收由用户负责手动执行。Codex 不自动调用真实 LLM 或工具，只准备 REFINE/REPLAN 切片、命令和脱敏报告格式。用户应通过 `start-local.ps1` 或本阶段明确的等价启动方式加载真实配置；未提供人工执行结果时，Live Replan Gate 状态为 `PENDING_MANUAL_ACCEPTANCE`，不得标记 M7 完成。



## 13. 阶段验收门

- [ ] 计划和状态可跨进程恢复；
- [ ] 所有修改版本化且可 diff；
- [ ] 旧版本不能覆盖新版本；
- [ ] 影响范围确定性可测；
- [ ] LOCAL 不改无关项；
- [ ] 终态前 G0～G5 全量通过；
- [ ] 用户事件中的航班、酒店、市内交通和政策事实仍经 Tool/Policy Port 核验；
- [ ] 首场会议变化会确定性重算到达时限、各去程候选的会前住宿需求和受影响能力；
- [ ] `return_scope=not_planned` 不会在重规划中被静默扩大；
- [ ] 用户手动执行的 Live Replan Gate 通过，且报告包含重复运行、真实失败、成本和延迟；
- [ ] 无 Action、反馈学习、自动订阅或 fallback；
- [ ] M6 Demo 增加一个局部重规划进阶案例。
