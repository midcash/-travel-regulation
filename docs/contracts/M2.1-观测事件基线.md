# M2.1-W1：观测事件字段与行为基线

状态：已冻结。本文件只定义后续 M2.1 步骤使用的观测契约，不接入运行时埋点。

## 范围与行为样本

本基线建立在已验收的 M2 契约之上：TripInteractionFacade、RouteDecision、
ConstraintSnapshot、ReadinessResult、TripState 和 WorkflowErrorPayload。它不修改 M2
业务判断，也不实现 M3 及之后的领域能力。

固定离线样本由 `tests/integration/test_m2_1_observability_baseline.py` 执行；所有 LLM
调用均使用显式 Fake，网络调用数为零。事件和报告不得持久化原始用户输入、Prompt、
完整计划或 legacy L2 问题原文。

| case_id | 当前行为基线 | 固定业务结果 |
| --- | --- | --- |
| `m21-plan-success` | M2 就绪 PLAN | `PLAN`、`RESEARCHING`、Snapshot v1、Gateway/Planner 各调用一次 |
| `m21-clarify` | 缺少规划 blocker | `CLARIFY`、`CLARIFYING`、四个 blocker、最多三个澄清问题、Planner 不调用 |
| `m21-interpreter-failure` | Interpreter 非法 JSON | `request_interpreter / INTERPRETATION_INVALID`、`FAILED`、Planner 不调用 |
| `m21-constraint-failure` | Constraint 无法归一化 | `constraint_service / INTERPRETATION_INVALID`、`FAILED`、Planner 不调用 |
| `m21-legacy-l2-revision` | legacy L2 触发一次修订 | 两轮、两次 Planner LLM 调用、L2 问题只保留测试内断言 |

当前基线中，失败后的 `TripState.last_error` 仍为空。第四步实现结构化错误链时，该项是
规格明确允许变更的状态字段；第一步不能提前变更它。

## 统一事件外壳

后续事件必须包含以下字段；字段名称、语义和类型在 M2.1 内冻结。

| 字段 | 类型/约束 | 用途 |
| --- | --- | --- |
| `event` | 下方事件名称 allowlist | 稳定事件类型 |
| `level` | `info`、`warning` 或 `error` | 事件严重级别 |
| `timestamp` | UTC RFC 3339 时间 | 事件产生时间 |
| `trace_id` | 应用层业务关联 ID | 跨 CLI、日志和工作流关联 |
| `otel_trace_id` | OTel 标准 Trace ID | Span 与应用日志关联 |
| `stage` | 下方阶段 allowlist | 当前工作流阶段 |
| `status` | 受控状态 | `started`、`succeeded`、`failed`、`clarifying`、`requested` 或 `exhausted` |
| `duration_ms` | 非负整数 | 阶段耗时；开始事件固定为 `0` |

`trace_id` 与 `otel_trace_id` 必须同时存在且语义不同；不得用 OTel ID 覆盖业务 ID，
也不得为缺失的请求关联生成 `default`。

事件名称 allowlist：

```text
workflow_started
workflow_completed
workflow_failed
stage_started
stage_completed
stage_failed
llm_call_started
llm_call_completed
llm_call_failed
legacy_review_completed
legacy_revision_requested
legacy_revision_completed
legacy_revision_exhausted
observability_emit_failed
```

阶段名称 allowlist：

```text
request
g0
request_interpreter
constraint_snapshot
readiness
route
state_persistence
legacy_plan
planner
l1
legacy_critic
legacy_revision
observability
```

## 字段白名单与脱敏

事件只能使用统一外壳和下表允许的附加字段。禁止对任意 Pydantic Model 调用
`model_dump()` 后直接写日志。

| 事件/阶段 | 允许的附加字段 |
| --- | --- |
| Workflow | `request_id`、`trip_id`、`session_id`、`workflow_status`、`state_version` |
| Request | `input_chars`、`identity_ref`、`state_version` |
| G0 | `passed`、`issue_codes`、`safety_flags`、`pii_present` |
| Interpreter | `prompt_version`、`schema_version`、`mode_hint`、`candidate_categories`、`candidate_count`、`confidence` |
| ConstraintSnapshot | `snapshot_version`、`constraint_count`、`constraint_categories`、`conflict_group_count` |
| Readiness | `ready`、`blocker_codes`、`blocker_ids`、`assumption_codes`、`confidence` |
| Route | `mode`、`reason_codes`、`required_capabilities`、`missing_blocker_ids` |
| State | `state_before`、`state_after`、`state_version_before`、`state_version_after`、`error_payload_ref` |
| Error | `category`、`code`、`safe_message`、`upstream_refs`、`retryable`、`cause_type` |
| LLM | `model`、`input_tokens`、`output_tokens`、`finish_reason`、`failure_type` |
| legacy Planner | `round`、`plan_chars` |
| legacy Review | `l1_passed`、`l1_issue_count`、`l2_passed`、`l2_issue_count`、`issue_refs` |
| legacy Revision | `round`、`trigger_sources`、`issue_refs`、`issue_summary_ref`、`output_chars`、`output_summary_ref` |
| observability failure | `component`、`failure_type` |

`issue_refs`、`issue_summary_ref` 和 `output_summary_ref` 必须是本次运行内的不可反推
引用；不得使用自由文本、普通文本哈希或自由文本推理链。

1. 永不记录原始用户输入、完整 Prompt、模型原始响应、完整计划、联系方式、证件、
   凭证、供应商原始 payload 或堆栈。
2. 错误事件只使用 `WorkflowError.public_payload()` 的 `safe_message`；非
   `WorkflowError` 只记录受控 `UNEXPECTED_INTERNAL_ERROR` 代码与异常类名。
3. 摘要在 presentation/application 边界通过显式白名单构造；领域模型不依赖 logger、
   OpenTelemetry 或 Metrics。
4. 观测发送失败必须产生独立安全告警，且不能改变业务返回值、异常、状态转换或
   LLM/工具调用次数。

## 观测等价性基线

第一步没有生产观测开关。测试使用仅存在于测试代码中的 Fake 包装器模拟“关闭/开启”
的安全摘要收集，并对每个 M2 样本比较：

- `RouteDecision`、`ClarificationRequest`、`ConstraintSnapshot` 与 `ReadinessResult`；
- `WorkflowError.public_payload()`、持久化 `TripState`、目标状态和版本；
- 测试进程内的 Prompt 内容、模型配置、Gateway/Planner 调用次数；
- strict 语义：无重试、缓存、fallback、估算或部分成功。

该包装器不是生产运行时埋点，不能被 `src/` 引用。第二步开始接入请求根 Trace 后，
仍必须保留上述业务等价断言。
