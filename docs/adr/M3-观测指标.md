# M3 第十二步：工具、Evidence 与 Candidate 观测指标

## 决策

M3 使用现有 `src.obs.metric` 的进程内 Prometheus 聚合指标，补充工具调用、Evidence 快照质量和 Candidate Pool 结果三组信号。指标只用于聚合监控，不替代 Trace、结构化日志或领域结果。

工具 Adapter 在一次 Provider 调用的成功或失败出口各记录一次：

- `tool_calls_total{provider,operation,status}`；
- `tool_duration_seconds{provider,operation}`。

Evidence Registry 在构造不可变快照后记录：

- `evidence_snapshots_total`；
- `evidence_items_total{evidence_status}`；
- `evidence_snapshot_coverage_ratio`；
- `evidence_snapshot_freshness_ratio`；
- `evidence_conflicts_total`；
- `evidence_missing_total`。

Candidate Pool 提供显式 `record_candidate_pool()` 汇总入口，供应用编排层记录：

- `candidate_pool_candidates_total{candidate_kind,candidate_outcome}`；
- `candidate_pool_rejections_total{reject_code}`；
- `candidate_pool_deferred_constraints_total`。

## 约束

所有标签值来自固定白名单；禁止使用 `trace_id`、`query_id`、`evidence_id`、`candidate_id`、`constraint_id`、原始供应商引用和自由文本。指标写入通过 `safe_increment()` / `safe_observe()`，导出器或标签失败只产生安全告警，不改变工具异常、Evidence 快照或 Candidate 结果。

Candidate Pool 位于领域层，不能依赖 `src.obs`。因此 M3 只提供聚合记录器，实际编排层在后续阶段拿到 `CandidatePoolResult` 后负责传入候选类型和拒绝代码；本步不改变筛选规则。

## 不在本步范围

本步不新增 HTTP metrics endpoint、OTel Span、告警规则、重试、缓存、备用供应商或任何成功降级语义。
