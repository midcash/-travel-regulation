# 项目方向卡

> 用途：作为后续业务优先、学习优先开发的长期方向摘要。它只记录稳定方向，不替代阶段卡、代码、测试或人工验收。

## 项目定义

这是一个企业商务差旅规划 Agent。它帮助员工或行政人员围绕一场首要会议，理解出发地、会议地点和到达时限，结合公司政策与动态交通事实，形成可解释、可追溯、证据不足时能够诚实失败的到会方案。

## 用户与产品边界

首版面向中国大陆境内、单人、单出发城市、单目的城市和一场首要会议。规划终点是首场会议的 `required_arrival_at`。会议期间住宿、会后住宿、返程、景点、活动、真实预订、付款、取消和改签不属于当前主链路；明确要求未支持能力时，应说明范围或拒绝，而不是假装完成。

## 稳定原则

LLM 负责自然语言理解和受控生成，外部工具负责动态事实，确定性代码负责时间、金额、Schema、权限、幂等和硬约束判断。实时事实必须能够追溯到来源和观察时间，关键事实缺失、过期、冲突或解析失败时必须显式失败或进入澄清。

项目优先证明一条真实可解释的业务切片，不提前建设通用平台、复杂持久化、完整 RAG、交易系统或生产韧性。任何新能力都先说明它解决的用户问题，再确定最小实现边界。

## 阶段方向

M0～M4 是通用内核历史，M4.1 是商务差旅评测基线；当前从 M4.2 的差旅语义与能力路由开始，之后再考虑 M4.3 的最小纵向切片、M5 的质量闭环和 M6 的交付层。M7～M9 属于后续扩展，不能因为已有文档就提前实现。

## 开发与验收原则

每个阶段只建立一张轻量阶段卡，写清用户问题、成功场景、失败场景、允许修改的模块、明确不做什么，以及结构和语义验收。实现优先采用垂直切片，先复现现状，再做最小变化；验收必须同时看代码结构、自动化测试、真实输入输出和人类可读结果。测试通过或 JSON 合法不能单独证明业务成立。

用户是业务取舍和是否进入下一阶段的最终决策者。AI 可以提出方案、解释技术、发现风险和执行已确认的改动，但不能通过扩大范围、修改验收含义或补写文档替用户做决定。

## 当前未决事项

当前尚未确定 M4.2 的第一个最小业务切片。进入实现前，需要先确定一个能展示“用户请求被正确理解，并据此决定需要哪些能力”的成功场景，以及一个信息不足时应澄清或安全失败的场景。
