# M2.1 Handoff Report

Stage: M2.1

Status: Step 8 end-to-end acceptance is complete. This report does not start M3 work.

## Delivered

M2.1 now has a local observability chain linked by the business `trace_id`: workflow start
and completion, M2 stage summaries, structured failures, LLM Spans, legacy Critic/L1/L2
review and revision events, and low-cardinality Metrics. Step 8 adds offline acceptance for:

- PLAN success;
- CLARIFY blocker localization;
- Interpreter failure and safe `WorkflowError` diagnostics;
- separate L1/L2 issue counts, issue refs, and one legacy revision;
- exclusion of raw input, prompts, responses, plans, and review text from events;
- telemetry failures isolated from business results, with an explicit failed-stage label.

- M2 is accepted: typed Interpreter, G0/G1, ConstraintService, clarification, and hybrid Router;
- M2.1 steps 1-7 froze event fields, root Trace, stage summaries, error chain, legacy audit,
  output channels, and Metrics;
- `tests/integration/test_m2_1_observability_baseline.py` retains M2 behavior and test-only
  observation-equivalence assertions;
- offline tests default to zero network, strict mode, no retry, no cache/fallback/partial success.

## Boundary for later stages

When M3 adds Tool Adapters, Evidence Registry, and Candidate Pool:

1. M3 owns its business contracts and state; log events are never domain inputs.
2. External facts enter downstream code only through M3 Provider/Evidence/TTL contracts.
3. New Agent/Tool Spans must be children of the current workflow/request context; do not forge
   parent IDs manually.
4. Metrics use stable low-cardinality labels only; candidate IDs, evidence IDs, request IDs,
   and free text are forbidden as labels.
5. Telemetry send failure must raise an independent safe warning but must not change a successful
   business result or enable fallback.

## Current limitations

- Local Metrics have no remote scrape endpoint; Prometheus Server and visualization belong to M6.
- Configuration or state loading before root Span creation still produces only a safe failure event.
- M2.1 adds no Live Gate; the existing M2 real-LLM Gate remains the Prompt/Schema quality gate.
