## End-to-end event sequence

`tests/e2e/test_m21_observability_acceptance.py` uses explicit Fakes and zero network calls.
Each observed event is checked for one business `trace_id`, one 32-character
`otel_trace_id`, a UTC timestamp, and a non-negative duration.

| Scenario | Evidence | Business result |
| --- | --- | --- |
| PLAN success | `workflow_started` - G0/Interpreter/Constraint/Readiness/Router/State events - `workflow_completed`; one Planner call | `PLAN`, successful state |
| CLARIFY | Readiness `blocker_codes` and Router `reason_codes=CLARIFICATION_REQUIRED` are locatable; zero Planner calls; final `workflow_completed` | `CLARIFY`, clarification state |
| Interpreter failure | Interpreter `stage_failed` and `workflow_failed` share the trace and include `stage=request_interpreter`, `code=INTERPRETATION_INVALID`, safe message, and duration | Original `WorkflowError` remains raised; no success event |
| legacy Critic revision | Two `legacy_review_completed` events; L1/L2 counts are separate; `legacy_revision_requested` and `legacy_revision_completed` share issue refs and round | Two revision rounds complete without changing the algorithm |

## Redaction and security

- The failure case asserts that raw user input is absent; errors retain only the safe
  `WorkflowError` message, stage, code, retryability, and cause type.
- The revision case asserts that the full plan, revised plan, and L2 issue text are absent;
  only issue refs, sources, counts, round, and length summaries remain.
- No prompt, raw LLM response, credential, contact information, or full itinerary fields
  were added to logs.
- Metrics still reject high-cardinality labels such as `trace_id`, `request_id`, `trip_id`,
  and `session_id`.

## Unresolved risks and accepted handling

1. M2.1 remains a local in-process Metrics/OTel/JSONL foundation. Prometheus Server, Jaeger,
   Phoenix, Langfuse, and remote alerting are out of scope until M6.
2. If bootstrap configuration or state loading fails before the root Span is created, the CLI
   can emit only a safe failure event and cannot form a complete `workflow_started` root Span.
   This does not affect the validated M2 request path accepted here.
3. No new live LLM Smoke was added. The existing M2 Live Gate remains authoritative for
   Prompt/Schema quality; M2.1 does not regrade it or switch to Fake after telemetry failure.

## M3 non-impact statement

M2.1 reads existing results at application/observability boundaries and emits redacted events.
`TripRequest`, `ConstraintSnapshot`, `ReadinessResult`, `RouteDecision`, and the M3
Provider/ToolError/Evidence/TTL/Candidate contracts and acceptance gates were not changed.
M3 may reuse the event envelope, Trace helpers, and Metrics, but its business code must not
require M2.1 events in order to run.
